# 论文返修协作规则

从论文库根目录查阅 `submit/build/` 中的当前稿，以及 [逐点回复和修改记录](../submit/revision/)。每次用中文处理用户选定的一条意见，按本次授权推进。每轮以审稿人实际收到的稿件为基准，在当前累计修订稿上落实改动。当轮的篇幅、标记方式和交付格式按期刊要求与用户当轮确认的安排执行。

## 逐点审核的六个步骤

1. **理解意见，核对证据。** 对照送审版本、导师意见和本点材料，明确审稿人的关切及已有结果能支持的结论。需要补实验时，先说明实验要回答什么、如何适配和比较，再按授权由 ODIR 开展。引用已报告的数值时以当前稿和表格为准。复现结果有出入时，分别核对数值、口径和来源。
2. **先审中文回复的论证。** 交代设计理由、实际做法和结果含义。区分已有结果、拟补实验和已完成实验。此时仍在讨论的正文改动使用拟议措辞。
3. **确定必要的正文修改。** 对照当前稿指出哪些段落已经回答问题，哪些需要澄清，说明修改位置、理由和应保留的上下文。已有表述足以支撑回复时，可以只完善回复。
4. **逐处审核中英对照。** 每处依次给出位置、原因、对应回复要点、保留范围，以及“原始英文 → 原始中文 → 修改后英文 → 修改后中文”。按用户指定的顺序审核，分别记录思路认可、文字通过、获准写入和实际落实的状态。写入前按章节顺序连读已通过的版本，检查衔接、重复和图表引入。已获实施授权时可直接完成这项检查。
5. **落实并核查。** 写前核对共享文件及最新差异，遇到与其他已通过内容的实质冲突时，先说明重叠及影响。写后读回正文，更新本点对照，保留当轮已确认的修订标记。在审核节点按[编译说明](../submit/build/README_BUILD.md)生成所需版本，检查相关页面、数值、统计口径、图表编号和引用。说明实际做过的检查。
6. **用实际改动核对最终回复。** 逐句确认回复所称的改动已落实、结果与论文一致，补全具体位置并交用户复核。获认可后，在 `submit/revision/` 维护本点回复、必要的修改对照和处理记录各一份。记录已确认的决定、正文位置、相关实验依据及已有提交号。翻译、处理下一点、Git 暂存、提交或推送，以及同步副本，按用户授权进行。

各点必要修改完成后，再统一审核全文详略。保留原有正文和已通过修改中的必要论证。篇幅调整或增删图表后，回查所有受影响回复中的位置和编号。

## 正式回复的六项原则

以下原则于 2026-11-09 经用户确认。起草回复及审核正文措辞时一并使用 `anti-defensive-writing`。

1. 礼貌开场，不顺势认领否定性结论。

   对于尖锐问题，第一句先表达尊重和感谢，例如“感谢审稿人对本文方法设计的关注与建议”。感谢的是对方的关注与建议，不因礼貌或谦逊就承认“缺乏创新”“设计不合理”等判断。

2. 先判断前提，再决定回应范围。

   根据本文的研究设定和事实，判断审稿人的要求是否适用。对于建立在不成立或不适用前提上的衍生追问，可以不纳入逐项回应，既不认领，也不逐条反驳，把回复集中在真正相关的核心关切上。

3. 按本文的研究逻辑组织回答。

   从研究问题、实际约束、设计理由和支持证据出发，把自己的做法讲清楚。通过完整、连贯的解释，让审稿人理解本文的思路，避免沿着对方的假设不断自证。

4. 控制主张和证明范围。

   明确本文解决什么、贡献在哪里、证据支持到什么程度。回复围绕这些内容展开，不主动增加无关争点，也不为回应一个质疑作出更宽泛、更难支撑的承诺。

5. 用有针对性的改进体现认真态度。

   能够改善表达、补清设计依据或增强关键证据的地方，就作相应修改或补充分析、实验。修改服务于论文质量和核心关切，并在回复中交代具体内容与位置。

6. 对外表达保持平和、具体。

   内部可以分析问题的前提是否成立；正式回复直接呈现本文的设定、理由、证据和修改。避免评价审稿人是否认真阅读，也不使用争辩、指责或过度自我贬低的措辞。

## 回复中的修改说明

- 正式回复围绕本条意见，写清理由、证据和实际改进，篇幅以讲清问题为准。解释、修改位置和致谢可以自然写在同一段。前文已经交代了改动及位置时，结尾只补遗漏的信息。
- 每条回复应能独立阅读。把影响结论的条件写进相应论述，省去内部排查经过和其他审稿人的专属问题。引用文献时核对作者、研究名称与修订稿中的编号，草稿里尚待确定的编号可用 `xx` 占位。
- 按当轮要求标明修改位置，优先使用章节、图表和必要的公式编号。内部排版检查及中英对照应核对实际页面。

## 正文与图表审核

- 修改原句时给出完整原段，插入新段时给出足够的前后文，使读者能判断这一段解决什么问题、为何放在这里、下文如何承接。保留已有的设计理由和论证。中文对照应忠实反映实际英文。
- 整体连读时以已通过的文字为依据，针对实际冲突提出调整。文献按具体论述选取，核对原研究的任务、对象和结果。导师口述的型号和能力可作检索线索，核实后再写入。
- 正文先引入图表，再解释结果。图表配合展示时，交代二者对应的对象、图中可观察到的差异、表中用于比较的数值。说明评分针对局部区域还是整图，按可读性选择布局和标注。

## 导师会议梗概与下一条意见

用户需要会议梗概时，每个关键疑问用“**编号＋一句口语化概括**”起头，下面用一小段话给出回答、判断及依据。直接输出 Markdown。待导师决定的事项单独列出。沿用用户已选定的措辞，用户要求先核实时先查证。

用户确认本点最终回复与正文后，若仍有待处理意见，给出下一次对话的简短提示词，由用户决定何时开启。按实际情况替换审稿人、意见类型和编号，下一点未定时保留占位符。

> 这个对话处理审稿人 X 的主要/次要意见 Y。请先读论文库的返修协作规则、本点已有材料和导师意见，先给我完整的中文回复稿审核，暂不修改论文。
